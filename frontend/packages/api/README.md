# @roleplay/api

Транспорт и схемы контракта бэкенда. Ни одного Vue-компонента и ни одного
доменного типа приложения.

## Точки входа

| Импорт | Содержит |
|---|---|
| `@roleplay/api/core` | `ApiClient`, `ApiError`, `NetworkError` |
| `@roleplay/api/gateway` | zod-схемы транспортных DTO и `parseResponse` |

## Разделение обязанностей

```text
ApiClient          знает про HTTP: базовый URL, токен, конверт {error, data}
gateway/schemas    знает про ФОРМУ JSON бэкенда (snake_case)
adapters (в приложении)  переводят DTO в доменную модель приложения
```

`ApiClient` не знает доменных типов. Адаптер не знает про `fetch`. Из-за этого
смена бэкенда затрагивает адаптеры, а смена транспорта — только клиент.

## Почему zod, а не только типы

TypeScript проверяет форму на сборке, данные приходят в рантайме. Ответ,
разошедшийся с контрактом, без схемы падает где-то глубоко в компоненте и
выглядит как баг фронтенда. Со схемой он падает на границе и указывает
эндпоинт.

## Генерируемый код

Если у бэкенда есть Swagger/OpenAPI, клиенты для него **генерируются**, а не
пишутся руками. Сгенерированный каталог коммитится, но правится только через
источник и генератор — правка «на месте» теряется при следующей генерации.
