# Правила для `frontend/`

Действуют вместе с корневым [`AGENTS.md`](../AGENTS.md).

## Workspace

- pnpm-команды выполняются **из `frontend/`**, если README пакета не задаёт
  более узкий cwd.
- Версии общих зависимостей — только через `catalog:`; внутренние — через
  `workspace:*`.
- Один lock-файл: `frontend/pnpm-lock.yaml`. Вложенные не создаются.
- Пакеты экспортируют `dist`. **Изменение `src` не доказывает поведение
  потребителя**: собери пакет и проверь реальный импорт.

## Границы пакетов

| Пакет | Знает про | НЕ знает про |
|---|---|---|
| `components` | Vue, стили, токены | HTTP, роутер, домен |
| `shared` | Vue-реактивность | стили, компоненты, Nuxt |
| `api` | HTTP, форму JSON бэкенда | Vue, домен приложения |
| `web` | всё перечисленное | — |

Компоненты приложения не импортируют `@roleplay/api` напрямую — только через
`app/contracts` и `app/adapters`.

## Стили

- Блок — класс, элемент — `&__`, **модификатор — HTML-атрибут**
  (`[variant="outlined"]`), а не класс `button--outlined`.
- Булев модификатор передаётся как `props.flag || undefined`.
- Изменяемые свойства выносятся в локальные CSS-переменные блока; вариант
  переопределяет переменные, а не повторяет правила.
- Цвет, отступ, шрифт, тень, z-index — только токены. Литералов в компонентах
  нет.
- `scoped` в приложении; **не** `scoped` в пакете компонентов.

Разбор — [`docs/frontend/scss-bem.md`](../docs/frontend/scss-bem.md),
[`docs/frontend/design-tokens.md`](../docs/frontend/design-tokens.md).

## Компоненты и композаблы

- Слоты для содержимого, props для конфигурации. Union вместо набора
  boolean-флагов.
- Доступность — часть компонента: доступное имя у иконки, связь label/input,
  `role="alert"` у ошибки, видимый фокус.
- SSR: обращение к `window`/`document` только после проверки; эффекты снимаются
  при размонтировании.
- Композабл возвращает управляемый интерфейс (`readonly` + методы) и снимает за
  собой через `onScopeDispose`.
- Новый публичный экспорт добавляется в allowlist
  `packages/components/test/public-surface.test.ts`.
- `<template>` не начинается с HTML-комментария: ведущий комментарий делает
  компонент multi-root, и атрибуты перестают попадать на корневой элемент.
  Пояснения — в `<script setup>`.
- Переключатели содержимого, таблицы и layout импортируются **синхронно**.
  Ленивая загрузка — только для изолированных тяжёлых кусков, открываемых явным
  действием: иначе быстрая навигация роняет приложение на `insertBefore`.

## Данные

- Приложение зависит от порта в `app/contracts`, а не от транспорта.
- Перевод DTO в доменную модель — только в адаптере.
- Новый домен получает **обе** реализации: `http` и `mock`.
- Выбор провайдера — только в `app/api/api.ts`.
- Пагинация, фильтр и сортировка остаются за API.
- **`await load()` сразу после мутации запрещён.** Между записью и её
  появлением в выдаче стоит асинхронный конвейер. Результат показывается
  локально через `useOptimisticList`, согласованность подтверждается
  ограниченным опросом `probeUntil`, оверлей снимается в любом исходе.

Разбор — [`docs/frontend/api-and-adapters.md`](../docs/frontend/api-and-adapters.md),
[`docs/frontend/eventual-consistency.md`](../docs/frontend/eventual-consistency.md).

## Производительность

Разбор и причины — [`docs/frontend/performance.md`](../docs/frontend/performance.md).

- Не загружай весь dataset ради клиентской пагинации, фильтра или сортировки.
- Интерактивное чтение с меняющимися параметрами обязано иметь
  latest-request-wins: устаревший ответ не перезаписывает новое состояние,
  старый запрос отменяется там, где транспорт это поддерживает.
- Отмена не показывается пользователю как ошибка сети.
- Опрос всегда ограничен бюджетом, использует backoff и может быть отменён.
- Не добавляй preload/prefetch/prerender и `will-change` «на всякий случай».
- Lazy import — только для изолированного тяжёлого куска по явному действию;
  layout, таблицы и быстро переключаемое содержимое остаются синхронными.
- Большая коллекция не рендерится целиком, если пользователь видит её часть.
- Новое контентное изображение резервирует геометрию; большой ассет получает
  responsive source; вероятный LCP-ресурс лениво не грузится.
- Performance-sensitive изменение измеряется на production-сборке до и после:
  `pnpm perf:bundle`.
- Микрооптимизация не становится общим правилом без профиля.

## Генерируемые файлы

```text
src/components/index.ts
src/assets/scss/_breakpoints.scss
src/utils/_breakpoints.ts
```

Правятся через источник (`src/breakpoints.json`, каталог `src/components`) и
`pnpm --filter @roleplay/components generate`.

Генератор обязан быть детерминированным: сортировка с явной локалью `"en"`,
никакой зависимости от порядка `fs.readdir`, проверка коллизий по регистру.
Повторный запуск не должен менять рабочее дерево — иначе репозиторий станет
вечно грязным у части команды
([`cross-platform.md`](../docs/conventions/cross-platform.md)).

## Проверка

```bash
pnpm build:local
pnpm lint
pnpm typecheck
pnpm test
```

`typecheck` обязателен: он ловит класс ошибок, невидимый для тестов — например
разворачивание вложенных ref-ов Pinia.

Покрытие считается только с `coverage.experimentalAstAwareRemapping: true`: без
него `.vue`, который лишь импортировали, показывает ложные 100%. Тесты
приложения разделены на `test/unit/**` (Node) и `test/nuxt/**` (окружение
Nuxt) — [`docs/frontend/testing.md`](../docs/frontend/testing.md).

При изменении `packages/*` дополнительно собери потребителя:

```bash
pnpm --filter @roleplay/web build
```

Не коммить `.nuxt`, `.output`, `dist`, `storybook-static`.
