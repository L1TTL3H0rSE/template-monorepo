# Дизайн-токены

Токен — это именованное решение. Компонент ссылается на решение, а не повторяет
его значение.

Все токены живут в `frontend/packages/components/src/assets/scss/`.

## Почему CSS-переменные, а не SCSS-переменные

| | SCSS `$var` | CSS `--var` |
|---|---|---|
| Когда вычисляется | На сборке | В рантайме |
| Переопределяется темой | Нет | Да |
| Переопределяется в скоупе | Нет | Да |
| Видно в DevTools | Нет | Да |
| Работает внутри `@media` в значении | Нет | Да |

SCSS-переменные остаются там, где значение действительно фиксировано на сборке
и используется в **селекторах**: брейкпоинты (`@media` не понимает CSS-
переменные) и z-index.

## Цвет

`colors.scss`. Имя описывает **роль**, а не оттенок:

```scss
--primary-main-color: #6c4bd8;    // ✔ роль
--purple-500: #6c4bd8;            // ✘ оттенок
```

Смена палитры с фиолетовой на синюю не должна требовать переименования
переменных по всему проекту.

Структура ролей:

```text
--text-*         текст: primary, secondary, placeholder, light, disabled
--primary-*      основное действие: main, hover, active, light, contrast
--secondary-*    вторичное действие
--success|warning|error|info-*   статусы: default, hover, active, contrast
--background-*   поверхности
--divider-*      разделители
--link-*         ссылки
--disabled-*     недоступное состояние
```

Каждый интерактивный цвет имеет минимум три значения: `default`, `hover`,
`active`. Компонент, у которого нет hover-состояния, выглядит сломанным.

### Исключение: значения для `rgba()`

```scss
--skeleton-light-color: 242, 241, 246;   // R,G,B без #
```

`rgba()` не принимает hex-переменную. Такие токены хранятся компонентами и
используются как `rgba(var(--skeleton-light-color), 0.5)`.

## Отступы

`spacings.scss` — шкала `--spacing-01` … `--spacing-15`.

```scss
--spacing-04: 0.5rem;   // 8px
--spacing-06: 1rem;     // 16px
--spacing-09: 2rem;     // 32px
```

Единицы — `rem`: интерфейс масштабируется вместе с системным размером шрифта
пользователя. `px` в отступах ломает доступность для людей, увеличивших шрифт в
системе.

Произвольное значение (`padding: 13px`) означает одно из двух: либо шкала
неполна, либо макет отклонился. Оба случая обсуждаются, а не решаются локально —
иначе интерфейс перестаёт быть ритмичным.

## Типографика

`_typography-api.scss` — placeholder-селекторы плюс миксин-фасад.

```scss
.card__title {
  @include typography(h-5);
}
```

### Почему `%placeholder` + `@extend`, а не миксин с телом

`@extend` склеивает все использования одного токена в **один** селектор готового
CSS:

```css
/* Итог: одно правило на все места */
.card__title, .modal__title, .list__title {
  font-family: Inter, Roboto, sans-serif;
  font-weight: 500;
  /* ... */
}
```

Миксин с телом скопировал бы пять свойств в каждое место. Разница на сотне
компонентов — десятки килобайт.

### Почему сверху ещё и миксин

```scss
@mixin typography($token) {
  @if $token == h-1 { @extend %h-1; }
  // ...
  @else { @error "Unknown typography token: #{$token}"; }
}
```

Опечатка в имени токена падает **на сборке** с внятным сообщением. Прямой
`@extend %h-55` дал бы менее очевидную ошибку, а забытый `%` — тихо неверный
результат.

### Шкала

```text
h-1 … h-6        заголовки
h-st-1, h-st-2   подзаголовки/метки
p-l, p-primary, p-m, p-s   основной текст
captions         подписи
forms-input-*    поля ввода
forms-button-*   подписи кнопок
```

Отдельные токены для форм существуют потому, что вес и трекинг подписи кнопки
отличаются от абзаца того же кегля.

## Брейкпоинты

Единственный источник — `src/breakpoints.json`. Из него генерируются оба
представления:

```bash
pnpm --filter @roleplay/components generate
```

```text
src/breakpoints.json
  ├─> src/assets/scss/_breakpoints.scss   $breakpoint-tablet: 767px;
  └─> src/utils/_breakpoints.ts           export const breakpoints = { tablet: 767 }
```

**Зачем генератор.** Брейкпоинт нужен и в CSS (`@media`), и в JS
(`useCustomBreakpoints`). Две рукописные копии расходятся ровно один раз — после
чего компонент переключается на мобильную вёрстку на одной ширине, а логика на
другой. Отладка такого расхождения занимает часы.

Оба сгенерированных файла коммитятся и помечены «не редактировать вручную».

## Тени, скругления, анимации

| Файл | Токены |
|---|---|
| `effects.scss` | `--shadow-01` … `--shadow-04`, миксин `focus-ring()` |
| `variables.scss` | `$radius-*`, `$z-index-*` |
| `transitions.scss` | `--transition-fast|base|slow`, `--transition-easing` |

### z-index — только из `variables.scss`

```scss
$z-index-popups: 1004;
$z-index-modal: 1003;
$z-index-mobile-menu: 1002;
$z-index-overflow-menu: 1001;
$z-index-tooltip: 1000;
```

Локальный `z-index: 9999` выигрывает один спор и проигрывает следующий: числа
перестают что-либо значить, и каждый новый слой требует числа побольше. Новый
слой добавляется сюда, со своим местом в порядке.

### `prefers-reduced-motion`

`transitions.scss` глушит анимации при системной настройке. Это не опция: для
части пользователей движение вызывает физическое недомогание.

## Витрина

Storybook → **Foundations / Design tokens** показывает цвета, шкалу отступов и
типографику.

Витрина существует не для красоты: без наглядного списка разработчик подбирает
значение на глаз, и в проекте появляется седьмой оттенок серого.

## Добавление токена

1. Значение в соответствующий `.scss` (или в `breakpoints.json`).
2. Для брейкпоинтов — `pnpm generate`.
3. При необходимости — строка в историю `DesignTokens.stories.ts`.
4. Проверить, что новый токен не дублирует существующий по смыслу.

Пункт 4 — главный. Токен, отличающийся от соседнего на 2% яркости, не решает
задачу, а удваивает выбор.
