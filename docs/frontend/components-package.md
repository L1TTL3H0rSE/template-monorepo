# Пакет компонентов

`frontend/packages/components` — дизайн-система: визуальные примитивы, токены,
витрина Storybook.

## Границы

Компонент дизайн-системы **не знает**:

| Не знает про | Почему |
|---|---|
| HTTP и API | Иначе его нельзя показать в Storybook без бэкенда |
| Роутер | Иначе пакет привязан к Nuxt и не собирается отдельно |
| Сторы приложения | Иначе компонент нельзя переиспользовать во втором приложении |
| Доменные типы | `Character` — понятие приложения, а не дизайн-системы |

Ссылка приходит через опции плагина, данные — через props:

```ts
nuxtApp.vueApp.use(componentsPlugin, { linkComponent: NuxtLink });
```

## Анатомия компонента

```vue
<script lang="ts" setup>
// 1. импорты
import { computed, ref } from "vue";

// 2. экспортируемые типы — рядом с компонентом, не в отдельном types.ts
export type ButtonVariant = "default" | "outlined" | "text" | "icon";
export type ButtonProps = { variant?: ButtonVariant; /* ... */ };

// 3. props со значениями по умолчанию
const props = withDefaults(defineProps<ButtonProps>(), { variant: "default" });

// 4. состояние и производные значения
const localLoading = ref(false);
const isLoading = computed(() => props.loading || localLoading.value);

// 5. обработчики
async function handleClick() { /* ... */ }
</script>

<template>…</template>

<style lang="scss">…</style>
```

Порядок блоков `script → template → style` зафиксирован правилом
`vue/block-order`: одинаковая структура делает диффы читаемыми.

### Типы объявляются в самом SFC

`export type ButtonProps` внутри `<script setup>` реэкспортируется барелем
(`export type * from "./Button.vue"`). Потребитель типизирует обёртку, не
заглядывая в исходник, а тип не может разойтись с реализацией — он и есть
реализация.

## Props: что можно и чего нельзя

### Слоты для содержимого, props для конфигурации

```vue
<!-- ✔ -->
<Card title="Заголовок">
  <p>Любое содержимое</p>
  <template #footer>…</template>
</Card>

<!-- ✘ попытка описать содержимое пропсами -->
<Card
  title="Заголовок"
  subtitle="…"
  bodyText="…"
  footerButtonLabel="…"
  footerButtonIcon="…"
/>
```

Второй путь заканчивается компонентом с двадцатью props, который всё равно не
покрывает следующий макет.

### Union вместо boolean-флагов

```ts
variant?: "default" | "outlined" | "text";   // ✔
outlined?: boolean; text?: boolean;          // ✘ что значит outlined+text?
```

Union делает невозможные комбинации непредставимыми.

### `defineModel` вместо ручной пары

```ts
const model = defineModel<string>({ default: "" });   // ✔
// вместо props.modelValue + emit("update:modelValue")
```

## Доступность — часть компонента, а не отдельная задача

Минимум, который проверяется при ревью:

| Требование | Пример из шаблона |
|---|---|
| Иконка без подписи несёт `aria-label` | `Button.accessibleLabel` |
| Поле связано с подписью через `id`/`for` | `TextField` + `useId()` |
| Ошибка объявляется сразу | `role="alert"` в `TextField` |
| Диалог помечен и закрывается по Escape | `Modal`, `aria-modal`, слушатель `keydown` |
| Декоративный элемент скрыт | `aria-hidden` у инициалов `Avatar` |
| Фокус виден | `@include focus-ring` в `:focus-visible` |

Убирать `outline` без замены нельзя: интерфейс становится непроходимым с
клавиатуры.

## Синхронный импорт против ленивого

`defineAsyncComponent` и динамический `import()` выглядят бесплатной
оптимизацией. Они таковой не являются для компонентов, которые участвуют в
переключении содержимого.

### Как это ломается

При быстрой навигации или переключении вкладки старый асинхронный компонент
дорезолвливается уже после того, как его место в DOM удалено. Vue пытается
вставить его рядом с несуществующим узлом:

```text
Failed to execute 'insertBefore' on 'Node':
The node before which the new node is to be inserted is not a child of this node.
```

Падает всё приложение, а стек указывает на рантайм Vue, а не на место ошибки.
Воспроизводится только быстрым кликом — то есть у пользователя, но не в
разработке.

### Правило

| Импортировать синхронно | Допустимо лениво |
|---|---|
| Переключатели содержимого (табы, свитчеры) | Модальные окна |
| Таблицы и списки внутри переключателей | Библиотеки графиков |
| Базовые layout-компоненты | Редакторы, кропперы, тяжёлые виджеты |
| Всё, что монтируется и размонтируется часто | То, что открывается по явному действию |

Критерий: лениво грузится **изолированный тяжёлый кусок, открываемый явным
действием пользователя**. Всё, что участвует в быстрой смене поддерева, —
синхронно.

Выигрыш от ленивой загрузки маленького компонента измеряется килобайтами, а
цена — падением приложения.

## SSR-безопасность

Компоненты рендерятся и на сервере, где нет `window` и `document`:

```ts
if (typeof document === "undefined") return;   // прямая проверка
import { isBrowser } from "../utils/browser";  // или утилита
```

Обращение к DOM без проверки роняет SSR — причём не в разработке, где чаще
работает клиентский режим, а на проде.

Побочные эффекты снимаются при размонтировании:

```ts
onBeforeUnmount(() => {
  unlockScroll();
  window.removeEventListener("keydown", onKeydown);
});
```

`Modal` снимает блокировку прокрутки даже при размонтировании в открытом
состоянии — иначе страница остаётся заблокированной навсегда.

## Публичная поверхность

`src/index.ts` — единственный вход. Всё, чего там нет, потребителем не
импортируется.

Guard: `test/public-surface.test.ts` сравнивает фактические экспорты с reviewed
allowlist и падает **в обе стороны**:

- экспорт исчез → ломаются потребители;
- появился незаявленный → внутренний хелпер стал публичным API, которое потом
  никто не решается убрать.

Внутренний код живёт в `src/internal` или рядом с единственным потребителем.

## Генерируемые файлы

| Файл | Источник | Команда |
|---|---|---|
| `src/assets/scss/_breakpoints.scss` | `src/breakpoints.json` | `pnpm generate` |
| `src/utils/_breakpoints.ts` | `src/breakpoints.json` | `pnpm generate` |
| `src/components/index.ts` | содержимое `src/components/*.vue` | `pnpm generate` |

Барель генерируется потому, что рукописный отстаёт от каталога, и новый
компонент оказывается недоступен без внятной ошибки.

## Сборка и отпечаток

Пакет публикует `dist`, а не `src`:

```json
"exports": {
  ".": { "types": "./dist/index.d.ts", "import": "./dist/index.js" },
  "./styles": "./dist/style.css",
  "./scss/*": "./src/assets/scss/*"
}
```

`./scss/*` — исключение: SCSS API отдаётся исходником, потому что его
подставляет препроцессор потребителя.

### Внешние зависимости не бандлятся

```ts
external: (source) => !(isAbsolute(source) || source.startsWith(".") || /* … */)
```

Vue, попавший внутрь бандла пакета, даст второй экземпляр рантайма в приложении:
`provide` из одного не виден `inject` из другого. `isAbsolute` обязателен —
точка входа приходит абсолютным путём, и без проверки Rollup объявляет внешним
сам entry.

### Отпечаток сборки

В бандл подставляется хеш содержимого `src`, и плагин пишет его в DOM:

```js
document.documentElement.dataset.roleplayComponentsBuild;
```

Это отделяет «правка неверна» от «потребитель загрузил старый бандл» — вторая
ситуация иначе выглядит как необъяснимое отсутствие изменений.

## Главная ловушка

> Правка в `src` **не видна** потребителю, пока пакет не собран.

```bash
pnpm --filter @roleplay/components build:local   # разово
pnpm --filter @roleplay/components build:watch   # в цикле разработки
```

Storybook при этом читает `src` напрямую, поэтому там изменения видны сразу.
Расхождение между «в Storybook работает, в приложении нет» почти всегда означает
несобранный пакет.
