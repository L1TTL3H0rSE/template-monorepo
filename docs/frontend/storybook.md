# Storybook

```bash
pnpm storybook          # http://localhost:6006
pnpm build:storybook    # статическая витрина
```

## Зачем он в этом шаблоне

Три задачи, каждая из которых иначе решается плохо:

1. **Разработка компонента без приложения.** Крайние состояния (загрузка,
   ошибка, длинный текст, отсутствие данных) в приложении воспроизводятся
   подбором данных; в истории они задаются одной строкой.
2. **Проверка всех веток стилей.** Если ветка есть в SCSS, но её нельзя открыть
   в витрине, глазами её не увидит никто — и она сломается незаметно.
3. **Каталог того, что уже есть.** Без него шестой вариант кнопки пишут заново,
   потому что не знали про существующий.

## Конфигурация

Storybook читает **тот же** `vite.config.ts`, что и сборка пакета. Отдельной
конфигурации сборки для историй нет: иначе компонент выглядит в витрине иначе,
чем в приложении, и витрина перестаёт быть доказательством.

`.storybook/preview.ts` делает три вещи:

```ts
app.use(createPinia());                       // сторы пакета работают
Object.entries(components).forEach(([name, component]) =>
  app.component(name, component));            // <Button/> как в приложении
```

Плюс viewports из того же `breakpoints.json`, что и SCSS-переменные — проверка
адаптива идёт ровно по границам, которые использует CSS.

## Что должно быть историей

> Каждая ветка стилей, которую нельзя увидеть в состоянии по умолчанию.

Для кнопки это: размеры, варианты, цвета, `disabled`, `loading`, поведение с
асинхронным обработчиком.

```ts
export const Sizes: Story = {
  render: (args) => ({
    components: { Button },
    setup: () => ({ args }),
    template: `
      <div style="display:flex;gap:12px;align-items:center">
        <Button v-bind="args" size="small" label="small" />
        <Button v-bind="args" size="medium" label="medium" />
        <Button v-bind="args" size="large" label="large" />
      </div>
    `,
  }),
};
```

Группа в одной истории, а не три отдельные: размеры сравнивают между собой, и
переключение вкладок этому мешает.

### Истории для крайних случаев

```ts
/** Битая ссылка не оставляет дыру в вёрстке — компонент падает на инициалы. */
export const BrokenImage: Story = {
  args: { src: "https://example.invalid/missing.png", size: "large" },
};
```

Именно такие истории окупаются: поведение при сбое иначе не проверяет никто.

### История с реальным взаимодействием

Для оверлеев история открывает компонент кнопкой, а не флагом `open: true`:

```ts
export const Default: Story = {
  render: (args) => ({
    components: { Modal, Button },
    setup: () => ({ args, open: ref(false) }),
    template: `
      <div>
        <Button label="Открыть" @click="open = true" />
        <Modal v-bind="args" v-model:open="open">…</Modal>
      </div>
    `,
  }),
};
```

Так проверяются переходы: блокировка прокрутки, закрытие по Escape и по клику
вне окна. Со статичным `open: true` они не выполняются вообще.

## Витрина токенов

`DesignTokens.stories.ts` показывает палитру, шкалу отступов и типографику.

Без неё разработчик подбирает цвет и отступ на глаз — так в проекте появляется
седьмой оттенок серого. Витрина токенов дешевле любого код-ревью, которое ловит
это постфактум.

## Организация

```ts
const meta: Meta<typeof Button> = {
  title: "Controls/Button",     // раздел/компонент
  component: Button,
  tags: ["autodocs"],           // автоматическая страница документации
  args: { label: "Действие" },  // общие args для всех историй
  argTypes: {
    variant: { control: "inline-radio", options: ["default", "outlined", "text"] },
  },
};
```

Разделы: `Foundations`, `Controls`, `Layout`, `Data display`, `Media`,
`Overlay`.

`argTypes` с явными `options` дают работающие контролы: без них Storybook
показывает текстовое поле, и опечатка в значении выглядит как поломка
компонента.

## Чек-лист истории

- [ ] Есть история на каждый вариант, размер и цвет.
- [ ] Есть `disabled` и `loading`, если компонент их поддерживает.
- [ ] Есть крайний случай: длинный текст, отсутствие данных, сбой загрузки.
- [ ] Оверлей открывается взаимодействием, а не флагом.
- [ ] `argTypes` описывают допустимые значения.
- [ ] Комментарий объясняет, что именно демонстрирует нетривиальная история.
