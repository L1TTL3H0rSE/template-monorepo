# Композаблы

Композабл — функция, которая инкапсулирует **состояние и его жизненный цикл**.
Не «функция с префиксом `use`».

## Признаки настоящего композабла

Функция заслуживает быть композаблом, если она делает хотя бы одно из:

- владеет реактивным состоянием (`ref`, `computed`, `reactive`);
- подписывается на что-то и обязана отписаться;
- использует другие композаблы или lifecycle-хуки.

Функция без состояния и без подписок — это утилита. Ей место в `utils/`, и
префикс `use` только вводит в заблуждение.

```ts
// ✘ не композабл — чистая функция без состояния
export function useFormatDate(date: Date) { return date.toISOString(); }

// ✔ утилита
export function formatDate(date: Date) { return date.toISOString(); }
```

## Правила

### 1. Возвращать состояние, а не сеттеры на него

```ts
// ✔ управляемый интерфейс
return {
  isOpen: readonly(isOpen),
  open: () => { isOpen.value = true; },
  close: () => { isOpen.value = false; },
};
```

`readonly` здесь не педантизм. Без него потребитель пишет
`disclosure.isOpen.value = true` в обход, и вся логика открытия — блокировка
прокрутки, установка фокуса — обходится молча. Ошибка проявится не там, где её
сделали.

### 2. Снимать за собой

```ts
export function useSearchQuery(options = {}) {
  let timer: ReturnType<typeof setTimeout> | undefined;

  // ...

  onScopeDispose(() => { if (timer) clearTimeout(timer); });
}
```

`onScopeDispose`, а не `onBeforeUnmount`: композабл может вызываться внутри
setup-стора или произвольного `effectScope`, где хука компонента нет вовсе.

Что происходит без этого: отложенный вызов срабатывает после ухода со страницы и
пишет в мёртвый scope. В разработке — предупреждение в консоли, на проде — утечка
памяти при каждом переходе.

### 3. Разделять «ввод» и «применённое значение»

```ts
const raw = ref("");       // что печатает пользователь
const applied = ref("");   // что пора отправлять в API
```

Одна переменная на оба смысла означает запрос к API на каждый символ.

### 4. Обрабатывать гонку

```ts
let currentRun = 0;

async function execute() {
  const run = ++currentRun;
  const result = await loader();

  if (run !== currentRun) return;   // устаревший ответ — выбрасываем
  data.value = result;
}
```

Без счётчика быстрый ввод в поиске даёт «моргание»: ответ на предыдущий запрос
приходит после текущего и затирает его.

### 5. `pending` снимается в `finally`

```ts
try {
  data.value = await loader();
} catch (caught) {
  error.value = caught;
} finally {
  pending.value = false;   // <- в обеих ветках
}
```

Самая частая ошибка ручной реализации: `pending = false` только в успешной
ветке, и неудачный запрос оставляет вечный скелетон.

### 6. Ошибка сбрасывается при новом запуске

Иначе успешный повтор показывает сообщение о прошлой неудаче.

## Где какой композабл живёт

| Расположение | Что там | Пример |
|---|---|---|
| `packages/components/src/composables` | UI-механика дизайн-системы | `useDisclosure`, `useCustomBreakpoints` |
| `packages/shared/src/**` | Переиспользуемое состояние без стилей | `useAsyncState`, `usePagination`, `useSearchQuery` |
| `applications/web/app/composables` | Состояние конкретного экрана | `useCharacterForm` |

Критерий переезда в `shared`: композабл понадобился второму приложению **и** не
зависит от стилей и компонентов.

## Композабл или стор

| | Композабл | Стор (Pinia) |
|---|---|---|
| Экземпляр | Свой на каждый вызов | Один на приложение |
| Живёт | Пока живёт scope | Пока живёт приложение |
| Подходит для | Формы, фильтра, локального состояния экрана | Сессии, списка, разделяемых данных |

Состояние формы в глобальном сторе показывает недописанный текст при следующем
открытии. Список, переоткрываемый с нуля при каждом возврате на страницу,
дёргает пользователя лишней загрузкой. Ошибка в обе стороны заметна не сразу.

Подробнее — [`state-and-stores.md`](state-and-stores.md).

## Именование

```ts
useCharacterForm()     // ✔ что даёт
useDisclosure()        // ✔
useCharacterFormData() // ✘ «Data» ничего не добавляет
useUtils()             // ✘ ни о чём
```

## Тестирование

Композабл тестируется как обычная функция. Если он использует lifecycle-хуки —
внутри `effectScope`:

```ts
const scope = effectScope();
const search = scope.run(() => useSearchQuery())!;

search.raw.value = "эйра";
await nextTick();
vi.advanceTimersByTime(300);
expect(search.applied.value).toBe("эйра");

scope.stop();
vi.advanceTimersByTime(1000);   // проверяем, что таймер снят
```

Последние две строки — самая ценная часть теста: они проверяют именно то, что
обычно забывают реализовать.
