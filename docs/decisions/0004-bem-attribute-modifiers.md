# ADR-0004: Модификаторы BEM — HTML-атрибуты

- **Статус:** accepted
- **Дата:** 2026-08-17
- **Область:** `frontend/packages/components`, стили приложений
- **Пересмотр в потомке:** появился первый собственный компонент со стилевыми модификаторами

## Контекст

Классический BEM записывает модификатор классом: `button--outlined`,
`button--large`, `button--primary`.

Во Vue-компоненте с несколькими независимыми осями (`variant`, `size`, `color`,
`loading`, `disabled`) это даёт конкатенацию строк прямо в разметке:

```vue
<button :class="[
  'button',
  `button--${props.variant}`,
  `button--${props.size}`,
  `button--${props.color}`,
  { 'button--loading': isLoading },
]">
```

У этой записи три конкретные проблемы:

1. Опечатка в шаблонной строке не ловится ничем — класс просто не сработает.
2. В DevTools элемент выглядит как `class="button button--primary
   button--medium button--outlined"`; какая ось какая — нужно разбирать глазами.
3. При добавлении оси имена начинают дублировать друг друга
   (`button--icon-small-error`).

## Решение

- **Блок** — класс: `.button`.
- **Элемент** — класс через `&__`: `.button__label`.
- **Модификатор** — HTML-атрибут: `[variant="outlined"]`, `[size="large"]`.
- **Булев модификатор** — наличие атрибута: `[subtle]`, `[interactive]`.

```vue
<button class="button" :color="props.color" :size="props.size" :variant="props.variant">
```

```scss
.button {
  &[variant="outlined"] { --button-border: solid 1px var(--button-accent-color); }
}
```

Булев модификатор передаётся как `props.subtle || undefined`: `:subtle="false"`
во Vue отрендерит `subtle="false"`, и селектор `[subtle]` сработает.

Дополнительно: изменяемые свойства выносятся в **локальные CSS-переменные**
блока, и вариант переопределяет переменные, а не повторяет набор правил.

## Рассмотренные варианты

### Классические классы-модификаторы

Знакомо всем и не требует объяснения. Цена — три проблемы из «Контекста». Для
компонента с одной осью разница незаметна; она проявляется на четвёртой.

### CSS Modules / утилитарные классы

Решают конфликт имён иначе. Цена: стиль перестаёт читаться как структура
компонента, а переопределение потребителем становится либо невозможным, либо
неуправляемым. Для библиотеки компонентов, которую расширяют приложения, это
существенно.

## Последствия

**Лучше:** значение модификатора приходит из props без склейки строк. Состояние
элемента читается в DevTools как есть. Множественные оси комбинируются
селекторами без взрыва имён.

**Платим:** специфичность `.button[variant="outlined"]` (0,2,0) выше, чем у
`.button` (0,1,0) — переопределить вариант снаружи одним классом не получится.
Компенсируется локальными переменными блока: потребитель меняет переменную, а не
воюет со специфичностью.

Второе: отклонение от канонического BEM нужно объяснять новому разработчику.
Этим документом и [`docs/frontend/scss-bem.md`](../frontend/scss-bem.md).

## Когда решение перестаёт действовать

Если проект перейдёт на утилитарный CSS-фреймворк или на CSS Modules, приём
теряет смысл вместе с самим BEM.
