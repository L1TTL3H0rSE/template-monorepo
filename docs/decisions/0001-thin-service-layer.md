# ADR-0001: Тонкий слой сервиса без моделей и репозиториев

- **Статус:** accepted
- **Дата:** 2026-08-17
- **Область:** `backend/*`
- **Пересмотр в потомке:** появился первый собственный слой сервиса

## Контекст

Классическая слоёная схема Go-сервиса содержит пять слоёв: контроллер → сервис →
репозиторий → доменная модель → строка БД.

`sqlc` с `emit_interface: true` уже даёт два из них:

- `query.Example` — структура с нативными Go-типами (`uuid.UUID`, `time.Time`,
  `*string`);
- `query.Querier` — интерфейс, пригодный для подмены в тестах.

При такой генерации дополнительные слои оказываются пустыми: доменная модель
повторяет строку БД поле в поле, а репозиторий проксирует методы `Querier`.

Цена — не абстрактная: добавление одной колонки требует правки в пяти местах, и
компилятор не подсказывает, какое из них забыли.

## Решение

Сервис состоит из трёх слоёв:

```text
internal/infra/http/controllers/   транспорт
internal/infra/services/           сценарий
internal/query/                    sqlc
```

Формы данных живут в `internal/domain/dtos`.

`internal/domain/models` и `internal/infra/repositories` **не заводятся по
умолчанию**. Сервис принимает `query.Querier` напрямую.

Интерфейс объявляется рядом с потребителем и только если у потребителя он есть:
его подменяют в тестах либо у него есть второй адаптер. Общего пакета `ports`
нет.

### Границы

Слой заводится, когда у него появляется собственная работа:

- **Репозиторий** — второй источник данных (кеш, внешний API), либо атомарная
  сборка результата из нескольких запросов в транзакции.
- **Доменная модель** — форма доказанно расходится со строкой БД: сущность
  собирается из нескольких таблиц, либо инвариант должен охраняться
  конструктором.

Причина фиксируется в плане задачи.

## Рассмотренные варианты

### Полная слоёная схема

Даёт единообразие и «правильно выглядит» на диаграмме. Цена: пять мест правки на
одну колонку, из которых компилятор проверяет два. На практике слои-пустышки
перестают обновлять, и они начинают врать.

### ORM вместо sqlc

Убирает ручной маппинг, но скрывает генерируемый SQL. Оптимизация запроса
превращается в обход ORM, а несоответствие схеме обнаруживается в рантайме.

## Последствия

**Лучше:** одна колонка — одна правка в SQL плюс регенерация. Тесты сценария
работают без БД через фейк `Querier`. Читать сервис можно за один проход.

**Платим:** схема отличается от «канонической», и её приходится объяснять
новому разработчику — этим документом. Появление настоящей потребности в слое
требует осознанного решения, а не следования шаблону.

**Риск:** соблазн положить SQL прямо в контроллер, раз слоёв мало. Контролируется
ревью и тем, что контроллер не импортирует `internal/query`.

## Когда решение перестаёт действовать

Если у большинства сервисов появляется второй источник данных или кеш —
репозиторий перестаёт быть исключением и должен войти в шаблон.
