# ADR-0006: Пакеты workspace экспортируют `dist`

- **Статус:** accepted
- **Дата:** 2026-08-17
- **Область:** `frontend/packages/*`

## Контекст

Пакет workspace может отдавать потребителю либо исходники (`src`), либо
собранный артефакт (`dist`).

Отдача `src` избавляет от шага сборки в цикле разработки. Взамен каждый
потребитель обязан уметь собрать чужой код: тот же препроцессор SCSS, те же
плагины Vite, та же версия TypeScript. Для Nuxt-приложения это означает
транспиляцию содержимого `node_modules`, а для Storybook и тестов — свою
конфигурацию каждого.

Кроме того, при отдаче `src` ошибка типов внутри пакета всплывает у
потребителя — в чужом контексте и с непонятным стеком.

## Решение

1. Пакеты публикуют собранный `dist`:

```json
"exports": {
  ".": { "types": "./dist/index.d.ts", "import": "./dist/index.js" },
  "./styles": "./dist/style.css"
}
```

2. Исключение — SCSS API: он отдаётся исходником (`./scss/*`), потому что его
   подставляет препроцессор потребителя.
3. Внешние зависимости (`vue`, `pinia`) **не бандлятся** в пакет: их
   предоставляет приложение.
4. Порядок сборки зафиксирован в `build:local`: `shared` → `api` →
   `components`.
5. В бандл подставляется отпечаток содержимого `src`, и плагин пишет его в
   `document.documentElement.dataset.componentsBuildFingerprint`.

## Рассмотренные варианты

### Экспорт `src`

Мгновенный цикл разработки без сборки. Цена: конфигурация сборки пакета
дублируется в каждом потребителе, а несовместимость версий инструментов
проявляется как необъяснимая ошибка в чужом коде.

### Бандлить зависимости внутрь пакета

Пакет становится самодостаточным. Цена: Vue попадает в бандл дважды, и
`provide` из одного экземпляра не виден `inject` из другого. Симптом выглядит
как «инъекция не работает» и стоит часов поиска.

## Последствия

**Лучше:** потребитель получает готовый ES-модуль и `.d.ts`. Ошибки типов
пакета падают при его сборке, а не у потребителя. Приложению не нужно знать, как
устроена сборка библиотеки.

**Платим:** правка в `src` **не видна** потребителю, пока пакет не собран. Это
самая частая ошибка первого дня.

Смягчается тремя способами: `pnpm build:local` перед запуском приложения,
`build:watch` в цикле разработки, и Storybook, который читает `src` напрямую.

Отпечаток сборки в DOM отделяет «правка неверна» от «загружен старый бандл» —
без него вторая ситуация выглядит как необъяснимое отсутствие изменений.

## Когда решение перестаёт действовать

Если у workspace остаётся ровно один потребитель и один общий конфиг сборки,
`dist` перестаёт что-либо покупать.
