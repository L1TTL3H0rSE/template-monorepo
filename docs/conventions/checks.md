# Обязательные проверки

Прогоняются **до** объявления задачи завершённой. Красная проверка — причина
остановиться, а не понизить порог.

## Проверка обязана уметь падать

Новая проверка — гейт, охранное правило, политика, preflight, дымовой прогон —
**не считается готовой на том основании, что зелёный случай зелёный**. Для
осмысленного инварианта должно существовать исполняемое доказательство
обратного:

```text
известно-хорошее состояние    -> PASS
представительное нарушение    -> FAIL
```

Опасен здесь не отказ проверки, а её мнимая работа: команда запускается, даёт
правдоподобный вывод и при этом не доходит до проверяемого места. Такое видно
только со стороны нарушения — зелёный результат выглядит одинаково и когда
инвариант держится, и когда его никто не проверял. Именно так выглядел реальный
случай: обязательный preflight не клал в запрос одно поле, падал раньше
провайдера — и потому не проверял о провайдере ровно ничего, хотя ради этого и
существовал.

Доказательством считается фикстура, негативный тест или утверждение, которое
краснеет при снятии критического условия, — не комментарий рядом с проверкой.
Примеры в этом репозитории:

| Проверка | Представительное нарушение |
|---|---|
| `scripts/dockerignore.test.mjs` | шаблон без `**/` |
| `scripts/adoption.test.mjs` | действующий ADR без условия пересмотра |
| `scripts/init-project.test.mjs` | предусловие перенесено после мутаций |
| `postgres_test.go: TestNameMustBeMeaningful` | `DB_NAME` пустой или из пробелов |
| `postgres_test.go: TestPublicOperationsRejectEmptyName` | `Validate` убран из `Connect` или `RunMigrations` |
| `template-identity.test.mjs` | замена и проверка остатков разошлись |
| `public-surface.test.ts` | каталог компонентов пуст |

Последние два — про частый вид мнимой проверки: утверждение, которое проходит
на пустом входе. Обход графа, перебор каталога и сравнение множеств обязаны
отдельно доказывать, что вход не пуст.

Особенно это касается проверок остатков шаблона, дрейфа генерации,
архитектурных границ, публичной поверхности, границ безопасности и политик CI:
все они легко проходят «ни на чём».

Правило не требует мутационного тестирования и не распространяется на обычные
модульные тесты: доказательство нужно **проверке**, а не каждому утверждению.

## Backend

Из каталога изменённого модуля:

```bash
go build ./...
go vet ./...
go test ./...
```

Если менялись `.sql` или миграции — до тестов:

```bash
go run github.com/magefile/mage generate:sqlc
```

Если менялись аннотации хендлеров:

```bash
go run github.com/magefile/mage generate:swag
```

После генерации `git status` должен быть чистым по сгенерированным файлам, либо
изменения в них должны быть осознанной частью задачи. Расхождение означает, что
кто-то правил генерируемый файл руками.

Модули проверяются **по отдельности**: красный `kit` не должен скрывать
состояние сервиса, и наоборот. Общей команды «прогнать весь backend» нет
намеренно.

Если менялся `magefile.go` — отдельно, из каталога модуля:

```bash
go run github.com/magefile/mage -l
go run github.com/magefile/mage lint
```

У Magefile тег сборки `//go:build mage`, поэтому `go build ./...`, `go vet ./...`
и `go test ./...` его НЕ собирают: зелёный прогон ничего не говорит о файле,
который в сборку не попал. `-l` компилирует Magefile и печатает цели, вторая
команда доказывает, что цель ещё и выполняется. Цель для этого берётся
безопасная: `database:up` доказала бы компиляцию ценой миграций в чужую базу.

Заявленная в `go.mod` версия Go — это **пол**, а не пожелание. Go по умолчанию
молча скачивает более новый тулчейн, если он требуется, и код начинает
опираться на API, которых на заявленной версии нет; расхождение всплывает у
того, кто соберёт проект без сети или на закреплённой версии. Проверка сборки
ровно на объявленном поле:

```bash
GOTOOLCHAIN=local go build ./...
```

Обязательна там, где версия Go имеет значение: при обновлении `go.mod`, при
использовании нового API стандартной библиотеки и в любом внешнем прогоне
(CI, агент), который претендует на воспроизводимость.

## Frontend

Из `frontend/`:

```bash
pnpm build:local   # пакеты собираются в порядке зависимостей
pnpm lint
pnpm typecheck
pnpm test
```

`pnpm typecheck` обязателен: он ловит класс ошибок, невидимый для тестов —
например разворачивание вложенных ref-ов Pinia
(см. [`frontend/state-and-stores.md`](../frontend/state-and-stores.md)).

Если менялись `packages/*`:

```bash
pnpm --filter @starter/web build   # потребитель должен собираться
```

Если менялись компоненты:

```bash
pnpm build:storybook
```

## Performance-sensitive изменения

Список признаков — в
[`frontend/performance.md`](../frontend/performance.md#19-что-считается-performance-sensitive-изменением):
новая runtime-зависимость, крупная библиотека на критичном маршруте, новый
глобальный CSS, шрифт, крупный ассет, preload/prefetch, изменение границ
разделения кода, рендеринга большого списка, поведения запросов или переноса
загрузки между SSR и клиентом.

Для таких изменений:

```bash
cd frontend
pnpm perf:bundle
```

Вывод «до» и «после» записывается в описание задачи там, где изменение
затрагивает размер бандла.

Уточнения, чтобы правило не превратилось в ритуал:

- это **не** проходной бюджет: пороговых значений в шаблоне нет и не выдумано
  ([`performance.md`](../frontend/performance.md#20-чего-в-шаблоне-намеренно-нет));
- обычные `build` / `lint` / `typecheck` / `test` остаются обязательными;
- опечатка в CSS не требует отчёта — правило действует для изменений с
  правдоподобным влиянием на производительность;
- измерение делается на **production**-сборке: `build:local` намеренно собирает
  пакеты без минификации и базой для performance-заявлений не является;
- будущий проект может превратить принятый бюджет в падающую проверку.

## Механика шаблона

При изменении идентичности, путей документации, раскладки ADR или памяти:

```bash
node --test "scripts/*.test.mjs"
node scripts/check-template-residue.mjs
node scripts/init-project.mjs --display-name "Acme Test" --slug acme-test \
  --repository-name acme-test --npm-scope @acme-test \
  --go-module-prefix example.com/acme-test --dry-run
```

Полный smoke-test делается на **временной копии** вне рабочего дерева: сборка
исходного шаблона не доказывает, что соберётся инициализированный проект
([`TEMPLATE.md`](../TEMPLATE.md)).

## Детерминизм генераторов

Генератор обязан давать одинаковый результат на любой машине. Проверка —
повторный запуск не меняет рабочее дерево:

```bash
pnpm --filter @starter/components generate
git status --short   # пусто
```

Непустой вывод означает, что порядок или регистр зависят от хоста, и репозиторий
будет вечно грязным у части команды. Разбор —
[`cross-platform.md`](cross-platform.md).

## Что нельзя пропускать

| Проверка | Что ловит | Чем не заменяется |
|---|---|---|
| `go test ./internal/infra/http` | Маршрут вне защищённой группы | Ничем: ручной обзор это пропускает |
| `go vet ./...` без исключений | Копирование protobuf-сообщений по значению | Отключение `copylocks` прячет и рукописные случаи |
| `pnpm typecheck` | Ошибки типов в шаблонах | Тесты не покрывают шаблоны |
| `pnpm build:local` | Расхождение `src` и `dist` | Тесты читают `src` напрямую |
| `sqlc generate` | Несоответствие SQL схеме | Тестами это проверять бессмысленно |
| Повторный `generate` + `git status` | Недетерминизм генератора | Проявится только на чужой машине |
| Повторный запуск `bootstrap` | Неидемпотентный засев | Первый запуск всегда «работает» |
| `mage -l` после правки `magefile.go` | Несобирающийся Magefile | `go build ./...` его исключает по тегу |

## Покрытие

```bash
pnpm test:coverage
```

Цифры имеют смысл только при AST-aware remapping: без него `.vue`, который
лишь импортировали, показывает 100%. С vitest 4 remapping включён всегда;
отдельной опции, которую можно забыть, больше нет. Разбор —
[`frontend/testing.md`](../frontend/testing.md).

Порог не подгоняется под текущую цифру. Покрытие, упавшее при честном
remapping, таким и было — просто это не было видно.

## Чек-лист завершения

- [ ] Проверки затронутой части зелёные.
- [ ] Сгенерированные файлы перегенерированы, а не отредактированы.
- [ ] Новый публичный НЕкомпонентный экспорт добавлен в allowlist
      `packages/components/test/public-surface.test.ts` (компоненты берутся из
      сгенерированного бареля и в списке не дублируются).
- [ ] Новая проверка имеет доказательство красного состояния — см. «Проверка
      обязана уметь падать».
- [ ] Новая переменная окружения есть в `.env.example`.
- [ ] Новый публичный маршрут добавлен в `publicRoutes` теста роутера
      **осознанно**.
- [ ] Новая ветка стилей имеет историю в Storybook.
- [ ] Новая фоновая задача берёт `pglock.TryWithinTx`.
- [ ] Мутация в сторе не делает `await load()` сразу после записи.
- [ ] Интерактивное чтение с меняющимися параметрами имеет latest-request-wins.
- [ ] Отмена запроса не показывается как ошибка сети.
- [ ] Новая команда `cmd/*` идемпотентна и завершается.
- [ ] Документ, описывающий изменённое поведение, обновлён в том же изменении.
- [ ] Сквозное решение зафиксировано ADR.

## Локальные артефакты

Не коммитятся: `dist`, `.nuxt`, `.output`, `storybook-static`, `node_modules`,
`bin`, `.env`.

Проверка перед коммитом:

```bash
git status --short
```

## Быстрый прогон всего

```bash
# механика шаблона
node --test "scripts/*.test.mjs"
node scripts/check-template-residue.mjs

# backend
(cd backend/kit && go build ./... && go vet ./... && go test ./...)
(cd backend/gotemplate && go build ./... && go vet ./... && go test ./...)

# frontend
(cd frontend && pnpm build:local && pnpm lint && pnpm typecheck && pnpm test)
```
