# Обязательные проверки

Прогоняются **до** объявления задачи завершённой. Красная проверка — причина
остановиться, а не понизить порог.

## Backend

Из каталога изменённого модуля:

```bash
go build ./...
go vet ./...
go test ./...
```

Если менялись `.sql` или миграции — до тестов:

```bash
go run github.com/magefile/mage generate:sqlc
```

Если менялись аннотации хендлеров:

```bash
go run github.com/magefile/mage generate:swag
```

После генерации `git status` должен быть чистым по сгенерированным файлам, либо
изменения в них должны быть осознанной частью задачи. Расхождение означает, что
кто-то правил генерируемый файл руками.

## Frontend

Из `frontend/`:

```bash
pnpm build:local   # пакеты собираются в порядке зависимостей
pnpm lint
pnpm typecheck
pnpm test
```

`pnpm typecheck` обязателен: он ловит класс ошибок, невидимый для тестов —
например разворачивание вложенных ref-ов Pinia
(см. [`frontend/state-and-stores.md`](../frontend/state-and-stores.md)).

Если менялись `packages/*`:

```bash
pnpm --filter @roleplay/web build   # потребитель должен собираться
```

Если менялись компоненты:

```bash
pnpm build:storybook
```

## Performance-sensitive изменения

Список признаков — в
[`frontend/performance.md`](../frontend/performance.md#19-что-считается-performance-sensitive-изменением):
новая runtime-зависимость, крупная библиотека на критичном маршруте, новый
глобальный CSS, шрифт, крупный ассет, preload/prefetch, изменение границ
разделения кода, рендеринга большого списка, поведения запросов или переноса
загрузки между SSR и клиентом.

Для таких изменений:

```bash
cd frontend
pnpm perf:bundle
```

Вывод «до» и «после» записывается в описание задачи там, где изменение
затрагивает размер бандла.

Уточнения, чтобы правило не превратилось в ритуал:

- это **не** проходной бюджет: пороговых значений в шаблоне нет и не выдумано
  ([`performance.md`](../frontend/performance.md#20-чего-в-шаблоне-намеренно-нет));
- обычные `build` / `lint` / `typecheck` / `test` остаются обязательными;
- опечатка в CSS не требует отчёта — правило действует для изменений с
  правдоподобным влиянием на производительность;
- измерение делается на **production**-сборке: `build:local` намеренно собирает
  пакеты без минификации и базой для performance-заявлений не является;
- будущий проект может превратить принятый бюджет в падающую проверку.

## Детерминизм генераторов

Генератор обязан давать одинаковый результат на любой машине. Проверка —
повторный запуск не меняет рабочее дерево:

```bash
pnpm --filter @roleplay/components generate
git status --short   # пусто
```

Непустой вывод означает, что порядок или регистр зависят от хоста, и репозиторий
будет вечно грязным у части команды. Разбор —
[`cross-platform.md`](cross-platform.md).

## Что нельзя пропускать

| Проверка | Что ловит | Чем не заменяется |
|---|---|---|
| `go test ./internal/infra/http` | Маршрут вне защищённой группы | Ничем: ручной обзор это пропускает |
| `go vet ./...` без исключений | Копирование protobuf-сообщений по значению | Отключение `copylocks` прячет и рукописные случаи |
| `pnpm typecheck` | Ошибки типов в шаблонах | Тесты не покрывают шаблоны |
| `pnpm build:local` | Расхождение `src` и `dist` | Тесты читают `src` напрямую |
| `sqlc generate` | Несоответствие SQL схеме | Тестами это проверять бессмысленно |
| Повторный `generate` + `git status` | Недетерминизм генератора | Проявится только на чужой машине |
| Повторный запуск `bootstrap` | Неидемпотентный засев | Первый запуск всегда «работает» |

## Покрытие

```bash
pnpm test:coverage
```

Цифры имеют смысл только при `coverage.experimentalAstAwareRemapping: true`:
без него `.vue`, который лишь импортировали, показывает 100%. Разбор —
[`frontend/testing.md`](../frontend/testing.md).

Порог не подгоняется под текущую цифру. Упавшее после включения remapping
покрытие таким и было — просто это не было видно.

## Чек-лист завершения

- [ ] Проверки затронутой части зелёные.
- [ ] Сгенерированные файлы перегенерированы, а не отредактированы.
- [ ] Новый публичный экспорт добавлен в allowlist
      `packages/components/test/public-surface.test.ts`.
- [ ] Новая переменная окружения есть в `.env.example`.
- [ ] Новый публичный маршрут добавлен в `publicRoutes` теста роутера
      **осознанно**.
- [ ] Новая ветка стилей имеет историю в Storybook.
- [ ] Новая фоновая задача берёт `pglock.TryWithinTx`.
- [ ] Мутация в сторе не делает `await load()` сразу после записи.
- [ ] Интерактивное чтение с меняющимися параметрами имеет latest-request-wins.
- [ ] Отмена запроса не показывается как ошибка сети.
- [ ] Новая команда `cmd/*` идемпотентна и завершается.
- [ ] Документ, описывающий изменённое поведение, обновлён в том же изменении.
- [ ] Сквозное решение зафиксировано ADR.

## Локальные артефакты

Не коммитятся: `dist`, `.nuxt`, `.output`, `storybook-static`, `node_modules`,
`bin`, `.env`.

Проверка перед коммитом:

```bash
git status --short
```

## Быстрый прогон всего

```bash
# backend
(cd backend/kit && go build ./... && go vet ./...)
(cd backend/gotemplate && go build ./... && go vet ./... && go test ./...)

# frontend
(cd frontend && pnpm build:local && pnpm lint && pnpm typecheck && pnpm test)
```
