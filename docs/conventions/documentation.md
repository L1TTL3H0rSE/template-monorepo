# Где что документируется

Каждый вид знания имеет ровно одно место. Дублирование гарантирует расхождение.

| Знание | Где | Живёт |
|---|---|---|
| Как устроен компонент | `README.md` рядом с ним | Пока жив компонент |
| Почему выбран приём | `docs/<область>/*.md` | Пока приём применяется |
| Почему принято сквозное решение | `docs/decisions/NNNN-*.md` | Навсегда, включая отменённые |
| Подтверждённая ловушка | `docs/PROJECT_MEMORY.md` | Пока верна |
| Почему написана эта строка | Комментарий в коде | Вместе со строкой |
| Что изменилось | Git | Навсегда |

## Комментарий в коде

Комментарий объясняет **почему**, а не **что**.

```go
// ✘ пересказ кода
// Увеличиваем счётчик
currentRun++

// ✔ причина
// Счётчик запусков: ответ на устаревший запрос должен быть отброшен, иначе
// быстрый ввод в поиске «моргает» предыдущим результатом.
currentRun++
```

Комментарий обязателен там, где код выглядит странно, но верен:

```go
// isAbsolute обязателен: точка входа приходит абсолютным путём, и на Windows
// он начинается с буквы диска — без этой проверки Rollup объявляет внешним сам
// entry и падает с «Entry module cannot be external».
```

Без такого комментария следующий читатель «упростит» условие и вернёт баг.

Комментарий **запрещён** там, где он пересказывает имя:

```go
// GetByID получает по ID   <- ничего не добавляет
```

### Doc-комментарий пакета

Каждый неочевидный пакет имеет `doc.go` или комментарий над `package`,
отвечающий на два вопроса: что здесь и **чего здесь быть не должно**.

Второй вопрос важнее: он предотвращает превращение пакета в свалку.

## README компонента

Отвечает на:

1. Что это и зачем.
2. Как запустить и проверить.
3. Какие границы (чего здесь быть не должно).
4. Главные ловушки.

Не отвечает на: как устроен каждый файл. Это читается в коде.

## Документ в `docs/`

Описывает **паттерн** и причины. Правило без причины нарушат при первом
неудобстве — потому что нечего взвесить.

Структура, которая работает:

```markdown
## Принцип
Короткая формулировка.

## Как это выглядит
Код из репозитория, а не выдуманный.

## Почему не иначе
Разобранная альтернатива и её цена.

## Что запрещено
Список с причиной для каждого пункта.
```

Примеры берутся из реального кода. Выдуманный пример устаревает молча — его
никто не компилирует.

## ADR

Заводится, когда решение:

- касается нескольких компонентов;
- имеет отвергнутые альтернативы, о которых будут спрашивать;
- дорого отменить.

Не заводится для решения внутри одного файла — там достаточно комментария.

ADR **не удаляется и не переписывается** после принятия. Отменённое решение
получает статус `superseded` и ссылку на новое: история решений и есть его
ценность.

Шаблон — [`decisions/_template.md`](../decisions/_template.md).

## Память проекта

`PROJECT_MEMORY.md` — подтверждённые факты и ловушки, которые трудно вывести из
одного очевидного файла.

Запись содержит: идентификатор, область, вывод, источники, дату проверки.

Чего там **не** должно быть: журнала выполненных задач (для этого Git), догадок,
секретов, длинных логов.

Если код опровергает запись — прав код. Запись исправляется или удаляется в том
же изменении.

## Правило синхронности

> Документ обновляется в том же изменении, что и код.

Документ, которому перестали доверять, хуже отсутствующего: его читают и делают
неверно. Отдельная задача «обновить документацию» не выполняется никогда.

## Язык

Документация и комментарии — по-русски, как весь проект. Идентификаторы, имена
файлов, коммиты — по-английски.

Термин, у которого есть устоявшийся английский вид (`composable`, `middleware`,
`fail-closed`), не переводится насильно.
