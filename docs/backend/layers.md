# Слои сервиса

## Форма

```text
cmd/  ->  config/  ->  internal/query/            (sqlc + Querier)
                   ->  internal/infra/services/   (сценарии)
                   ->  internal/infra/http/       (транспорт)
                   ->  internal/domain/dtos/      (формы)
                   ->  pkg/                       (публичные контракты)
```

Три слоя, а не пять. Это главное решение шаблона, и оно требует объяснения.

## Чего в шаблоне нет намеренно

### Нет `internal/domain/models`

sqlc уже отдаёт нативные Go-типы: `uuid.UUID`, `time.Time`, `string`, `*int64`.
Доменная модель поверх такой строки оказывается маппингом поля в поле того же
типа:

```go
// Чего мы НЕ делаем:
func toModel(row query.Example) models.Example {
    return models.Example{ID: row.ID, Name: row.Name, CreatedAt: row.CreatedAt}
}
```

Такой код не добавляет ни одной проверки и ни одного правила. Он добавляет
третье место, которое нужно править при добавлении колонки.

**Когда модель всё-таки заводится:** доменная форма доказанно расходится со
строкой БД — например, сущность собирается из трёх таблиц, или инвариант
(«период не может быть отрицательным») должен охраняться конструктором. Причина
фиксируется в ADR.

### Нет `internal/infra/repositories`

Сгенерированный `query.Querier` уже является интерфейсом. Рукописный
`store`-интерфейс поверх него повторяет те же методы и ничего не добавляет:

```go
// Чего мы НЕ делаем:
type ExampleStore interface {
    GetExample(ctx context.Context, id uuid.UUID) (query.Example, error)
}
```

Сервис принимает `query.Querier` напрямую, и он же служит тестовым швом —
см. [`testing.md`](testing.md).

**Когда репозиторий появляется:** второй источник данных (кеш, внешний API,
файловое хранилище) или необходимость атомарно собрать результат из нескольких
запросов в транзакции. То есть когда у слоя появляется собственная логика, а не
только проброс.

### Нет общего пакета `ports`

Интерфейс объявляется **рядом с потребителем** и только если у потребителя он
действительно есть:

```go
// internal/infra/http/controllers/example/example.go
//
// Интерфейс живёт здесь, потому что здесь его ПОТРЕБЛЯЮТ. И существует он
// потому, что на нём держатся тесты хендлера.
type service interface {
    GetByID(ctx context.Context, id uuid.UUID) (*dtos.ExampleView, error)
    // ...
}
```

Общий пакет `ports` собирает интерфейсы в одном месте — и тем самым
восстанавливает связность, которую интерфейсы должны были убрать: любое
изменение сигнатуры трогает общий каталог, который видят все.

Критерий «у интерфейса есть потребитель»: его подменяют в тестах либо у него
есть второй адаптер. Интерфейс с единственной реализацией и без тестов — это
лишний файл.

### Нет `internal/infra/httperr`

Перевод ошибки в HTTP-статус живёт в `kit/ginx.WriteDomainError` — см.
[`errors.md`](errors.md). Свой перевод в каждом сервисе означает, что
одинаковый сценарий даёт 404 в одном сервисе и 500 в другом.

## Обязанности слоёв

### Контроллер

Отвечает за **транспорт**: разобрать запрос, вызвать сценарий, оформить ответ.

```go
func (h *Handler) GetByID(c *gin.Context) {
    p := ginx.NewGinxParser(c)

    id, err := p.GetPathUUID("id")          // разбор
    if err != nil {
        ginx.WriteErrorResponse(c, ginx.BadRequest)
        return
    }

    view, err := h.svc.GetByID(c.Request.Context(), *id)  // сценарий
    if err != nil {
        ginx.WriteDomainError(c, h.log, err)              // категория -> статус
        return
    }

    ginx.WriteSuccessResponse(c, view)      // форма ответа
}
```

Чего в контроллере быть не должно: SQL, бизнес-правил, `if` по ролям
пользователя, ручного `c.Param` + `uuid.Parse`.

### Сервис

Отвечает за **сценарий**: последовательность шагов, правила, переводы ошибок в
доменные категории.

```go
func (s *Service) GetByID(ctx context.Context, id uuid.UUID) (*dtos.ExampleView, error) {
    row, err := s.q.GetExample(ctx, id)
    if err != nil {
        if errors.Is(err, pgx.ErrNoRows) {
            return nil, fmt.Errorf("%w: example %s", errorsx.ErrNotFound, id)
        }
        return nil, err
    }

    return toView(row), nil
}
```

Сервис не знает про `gin.Context`, HTTP-статусы и заголовки. Проверить это
просто: если из сервиса убрать HTTP, он должен продолжать компилироваться.

### `dtos`

Единственный слой форм. Input/Patch связываются напрямую и с HTTP-телом, и с
внутренними вызовами; View — форма ответа.

Отдельные `request.go` в контроллерах не заводятся. `response.go` остаётся:
это типизированные схемы swagger, специфичные для одного эндпоинта.

## Правило добавления слоя

> Новый слой заводится под **доказанного потребителя**, а не «по симметрии».

«У сервиса A есть репозиторий, значит и у B должен быть» — не причина.
Причина — конкретная задача, которую без слоя решить нельзя.

Обратное тоже верно: как только у слоя появляется настоящая работа, его надо
завести, а не размазывать её по соседям.
