# Межсервисные контракты

Документ описывает паттерн, по которому сервисы общаются между собой. В шаблоне
он зафиксирован файлами `backend/gotemplate/proto/*.proto`; конкретный
кодогенератор не завендорен — выбор остаётся за проектом (см.
[`ADR-0002`](../decisions/0002-proto-first-contracts.md)).

## Правило владения

> Subject, форму сообщения и версию объявляет **владелец данных**.

Потребитель импортирует сгенерированный клиент владельца. Он не пишет строку
subject у себя, не копирует тип сообщения и не делает re-export.

```text
backend/gousers/proto/rpc.proto      <- владелец объявляет
backend/gousers/pkg/rpc/             <- генератор порождает
backend/gocharacters/internal/...    <- потребитель импортирует pkg/rpc владельца
```

Копия строки `"rpc.v1.users.read_one"` у потребителя выглядит безобидно ровно до
того дня, когда владелец переименует subject. Компилятор промолчит, а запрос
уйдёт в никуда.

## Почему proto-first, а не JSON

| | JSON | proto-first |
|---|---|---|
| Схема | в голове или в вики | в файле, в репозитории владельца |
| Несовместимое изменение | обнаруживается в проде | обнаруживается на генерации |
| Клиент | пишется руками у каждого потребителя | генерируется |
| Версия | «вроде добавили поле» | номер в имени сообщения и subject |

Главное свойство: контракт становится **артефактом**, который можно
сгенерировать, сравнить и проверить в CI, а не договорённостью.

## Пространства имён

```text
rpc.v1.<домен>.<метод>        синхронный вызов
events.v1.<домен>.<событие>   асинхронное событие
```

Версия входит в subject. Несовместимое изменение — это `v2`, а не правка `v1`:
у `v1` уже есть потребители, которые деплоятся отдельно и не обязаны обновляться
одновременно.

## Синхронный вызов и событие

| | RPC | Событие |
|---|---|---|
| Когда | Нужен ответ прямо сейчас | Факт уже произошёл |
| Связность | Вызывающий зависит от доступности вызываемого | Не зависит |
| Пример | «существует ли пользователь X?» | «персонаж создан» |

Правило выбора: если вызывающий может продолжить без ответа — это событие.
RPC-вызов ради «уведомить» превращает независимые сервисы в один распределённый
монолит: падение любого роняет всех.

## Совместимость

Совместимые изменения:

- добавление **опционального** поля;
- добавление нового метода/события;
- расширение перечисления новым значением (если потребители обрабатывают
  неизвестное значение).

Несовместимые (требуют новой версии):

- удаление или переименование поля;
- смена типа поля;
- смена смысла поля при том же имени — самое опасное, потому что не ловится
  ничем автоматическим.

## Генерируемый код

`pkg/rpc/` и `pkg/events/` содержат сгенерированные файлы с пометкой
`Code generated ... DO NOT EDIT`. Они коммитятся, но правятся только через
`.proto` и генератор.

Проверка в CI: перегенерировать и сравнить с закоммиченным. Расхождение —
ошибка сборки, а не предупреждение.

## Сгенерированные сообщения передаются только по указателю

Структуры, порождённые `protoc-gen-go`, содержат внутреннее состояние с
`sync.Mutex` (через `protoimpl.MessageState`). Копирование такой структуры —
копирование мьютекса, и `go vet` справедливо на это ругается:

```text
passes lock by value: rpc.ExampleReadOneRequest contains sync.Mutex
```

```go
func handle(req rpc.ExampleReadOneRequest) error   // ✘ значение
func handle(req *rpc.ExampleReadOneRequest) error  // ✔ указатель
```

Это касается и возврата, и элементов срезов: `[]*rpc.Item`, а не `[]rpc.Item`.

### Отключать проверку — неверный ответ

Соблазн погасить `copylocks` в CI понятен: ошибка приходит из
сгенерированного кода, который никто не писал руками. Но проверка не ложная —
копия protobuf-сообщения ломает внутреннее состояние библиотеки и является
ошибкой в любом случае. Отключение прячет вместе с ней все остальные
копирования мьютексов в проекте, включая рукописные.

Правило: указатель везде, а `go vet ./...` остаётся без исключений
(см. [`checks.md`](../conventions/checks.md)).

## Данные соседнего домена

Сервис не читает таблицы соседа и не ставит внешний ключ в чужую БД. Ссылка
хранится как идентификатор, а её валидность проверяется через публичный контракт
владельца:

```go
// Проверка существования — через контракт владельца, а не SELECT в чужую базу.
if _, err := usersClient.ReadOne(ctx, &usersrpc.ReadOneRequest{Id: authorID}); err != nil {
    return fmt.Errorf("%w: unknown author %s", errorsx.ErrValidation, authorID)
}
```

Цена — сетевой вызов. Что покупается: владелец может менять свою схему, не ломая
соседей, и сервисы деплоятся независимо.

## Чек-лист изменения контракта

1. Правка `proto/` **у владельца**.
2. Перегенерация `pkg/rpc` / `pkg/events`.
3. Обновление обработчика владельца.
4. Обновление всех известных потребителей.
5. Тесты у владельца и у потребителей.
6. Если изменение несовместимо — новая версия, а не правка старой.

Пункт 4 — причина, по которой копии контрактов запрещены: список потребителей
находится поиском по импорту `pkg/rpc` владельца. Копия из этого поиска
выпадает.
