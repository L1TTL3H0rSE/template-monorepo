# Разрешения

## Три разных вопроса

Их постоянно смешивают, и от этого берётся большинство дыр в доступе.

| Вопрос | Кто отвечает | Где проверяется |
|---|---|---|
| Кто ты? (аутентификация) | Гейтвей по токену | `GatewayRequireAuth` на группе роутера |
| Кем ты числишься? (роль) | Провайдер identity | `GatewayRequireRole`, если нужно |
| Можно ли тебе ЭТОТ объект? | **Владелец данных** | Внутри сценария |

Третий вопрос — единственный настоящий контроль доступа. Первые два его не
заменяют.

## Почему роль — не доступ

```go
// Так делать НЕЛЬЗЯ:
api.PATCH("/characters/:id", middlewares.GatewayRequireRole("author"), h.Update)
```

Роль `author` говорит, что пользователь вообще может редактировать персонажей.
Она ничего не говорит о том, что он может редактировать **этого** персонажа.
Проверка выглядит как защита, но пропускает редактирование чужой анкеты.

Правильно:

```go
func (s *Service) Update(ctx context.Context, actorID, characterID uuid.UUID, patch dtos.CharacterPatch) (*dtos.CharacterView, error) {
    row, err := s.q.GetCharacter(ctx, characterID)
    if err != nil {
        if errors.Is(err, pgx.ErrNoRows) {
            return nil, fmt.Errorf("%w: character %s", errorsx.ErrNotFound, characterID)
        }
        return nil, err
    }

    // Решение принимает владелец данных: у него есть и объект, и субъект.
    if row.AuthorID != actorID {
        return nil, fmt.Errorf("%w: not the author", errorsx.ErrForbidden)
    }
    // ...
}
```

Решение принимается там, где известны **и субъект, и объект**. Middleware знает
только субъекта, поэтому такую проверку сделать не может в принципе.

## Fail-closed

Отказ — состояние по умолчанию. Разрешение выдаётся только при явно выполненном
условии.

```go
// Так делать НЕЛЬЗЯ: недоступность проверки открывает доступ.
allowed, err := s.checkAccess(ctx, actorID, characterID)
if err != nil {
    s.log.Warn("access check failed", zap.Error(err))
    allowed = true   // <- fail-open в контроле доступа
}
```

Fail-open допустим для rate limit (см. [`http.md`](http.md)) и недопустим для
доступа: там цена ошибки — утечка, а не лишний запрос.

## Каталог разрешений владельца

Каждый сервис объявляет свои действия и ресурсы в `pkg/permissions`:

```go
const (
    ServiceCode = "gotemplate"

    ActionExampleRead   = "example.read"
    ActionExampleManage = "example.manage"

    ResourceTypeExample = "gotemplate.example"
)

func Catalog() []Permission { /* ... */ }
```

Три причины, по которым это `pkg/`, а не `internal/`:

1. Другой сервис, которому нужно сослаться на действие, импортирует **константу
   владельца**, а не копирует строку.
2. Интерфейс администрирования строит список прав из `Catalog()`, а не из
   рукописного справочника, который забывают обновлять.
3. Переименование действия становится ошибкой компиляции у всех, кто на него
   ссылается.

## Соглашение об именах

```text
<ресурс>.<действие>       example.read, example.manage
<сервис>.<ресурс>         gotemplate.example
<сервис>.<область>        gotemplate.control
```

`manage` объединяет создание, редактирование и удаление. Дробить его на
`create`/`update`/`delete` стоит только тогда, когда в системе действительно
есть роль, которая может создавать, но не может удалять. Три права вместо одного
«на всякий случай» — это три места, где можно ошибиться.

## Публичные маршруты

Маршрут вне защищённой группы должен быть в списке `publicRoutes` теста роутера.
Список ведётся вручную намеренно: добавление публичного маршрута — решение с
последствиями, и оно должно проходить через правку теста, а не появляться
незамеченным.

## Чек-лист привилегированного действия

- [ ] Маршрут внутри группы с `GatewayRequireAuth`.
- [ ] Субъект берётся из доверенного контекста, а не из тела запроса.
- [ ] Решение принимается в сценарии, где известен и субъект, и объект.
- [ ] Отказ — состояние по умолчанию; ошибка проверки означает отказ.
- [ ] Отказ возвращается категорией `errorsx.ErrForbidden`.
- [ ] Действие объявлено в `pkg/permissions` владельца.
